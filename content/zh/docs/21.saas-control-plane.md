# SaaS 控制中心

APay 的 `saas-control-plane` 是可选的商业控制面模块，不是 Shoply 业务代码，也不属于 Minimal 主题。APay 继续负责 SaaS 官网、商品、支付和订阅订单；外部 SaaS 继续拥有租户、店铺和运行数据。控制中心只通过 Provider API 交互，不直连外部业务数据库。

## 启用与配置

模块默认随 APay 构建启用，设置 `APAY_SAAS_CONTROL_PLANE_ENABLED=false` 可关闭页面和 `/api/saas-control-plane/admin/**` API。生产环境必须设置至少 32 字符的 `APAY_SAAS_CREDENTIAL_KEY`；它用于 AES-256-GCM 加密 Provider 凭证，丢失密钥或未迁移就更换密钥会导致已有凭证无法解密。仅本地开发需要连接私网地址时才设置 `APAY_SAAS_ALLOW_PRIVATE_NETWORK=true`。

管理员打开 `/admin/saas` 后可添加多个 Provider 连接，并指定默认连接。每个连接包含名称、Provider、API 地址、服务端管理凭证、启用状态和默认状态。读取接口只返回凭证掩码，不返回密文或原文。

## Provider 契约

首个适配器是 Shoply，固定读取以下上游能力：

- `dashboard/summary`：运营总览；
- `store/list`：租户和店铺列表；
- `plan/list`：套餐列表；
- `subscription/list`：订阅列表。

浏览器只访问 `/api/saas-control-plane/admin/**`，不能指定任意上游路径。模块请求 Shoply 时使用服务端保存的 `x-auth`，30 秒超时，并校验 HTTP 状态和业务 `code=0`。

## 权限与写操作

页面和只读模块 API 使用 `ext:saas-control-plane:dashboard` 权限；连接新增、编辑、删除和测试还要求 `settings:edit`。修改 Provider API 地址时必须重新输入凭证，避免旧凭证被发往新主机。主管理员和 `*` 权限保持全量访问。

V1 只允许修改 Provider 连接配置，不修改 Shoply 店铺、套餐或订阅。以后增加外部业务写操作前，必须为每种操作定义固定能力、稳定幂等键、审计记录、失败补偿和明确回滚边界，不能开放通用代理接口。
