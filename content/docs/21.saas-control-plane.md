# SaaS Control Plane

APay's `saas-control-plane` is an optional commercial control-plane module. It is neither Shoply business code nor part of the Minimal theme. APay remains responsible for the public website, products, payments, and subscription orders, while each external SaaS remains the owner of its tenants and runtime data. The module only uses Provider APIs and never connects to an external product database.

## Enable and configure

The module is enabled at build time by default. Set `APAY_SAAS_CONTROL_PLANE_ENABLED=false` to remove its page and `/api/saas-control-plane/admin/**` API. Production must provide `APAY_SAAS_CREDENTIAL_KEY` with at least 32 characters. It protects Provider credentials with AES-256-GCM; losing or rotating the key without a migration makes stored credentials unreadable. Set `APAY_SAAS_ALLOW_PRIVATE_NETWORK=true` only for local development that must call a private Provider host.

Administrators use `/admin/saas` to create multiple Provider connections and choose a default. A connection contains a name, Provider, API URL, server-side credential, enabled state, and default state. Read APIs return only a credential preview, never plaintext or ciphertext.

## Provider contract

The initial Shoply adapter has a fixed read-only capability set:

- `dashboard/summary` for the operational overview;
- `store/list` for tenants and stores;
- `plan/list` for plans;
- `subscription/list` for subscriptions.

The browser only calls `/api/saas-control-plane/admin/**` and cannot choose an arbitrary upstream path. The module calls Shoply with the stored server-side `x-auth`, a 30-second timeout, and validation of both HTTP status and business `code=0`.

## Permissions and mutations

The page and read-only module API require `ext:saas-control-plane:dashboard`. Creating, editing, deleting, or testing connections additionally requires `settings:edit`. Changing a Provider URL requires the credential to be entered again so an existing secret cannot be sent to a new host. The primary administrator and `*` grants retain full access.

V1 only mutates Provider connection configuration. Before any Provider business mutation is introduced, it must define a fixed capability, stable idempotency key, audit trail, failure compensation, and rollback boundary. A generic upstream proxy is not permitted.
